# Разработка Data X-Ray

Проверенная среда: Windows и Python 3.12.14. Из корня проекта создайте окружение и установите зафиксированные зависимости:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

После каждой законченной итерации выполните полный набор с настоящей Windows-платформой Qt. Проверяйте код завершения команды: `passed` не означает успех, если Qt затем аварийно завершился.

```powershell
$env:QT_QPA_PLATFORM = 'windows'
.\.venv\Scripts\python.exe -m pytest -q
if ($LASTEXITCODE -ne 0) { throw 'Полный набор тестов завершился ошибкой' }
```

В полном наборе уже есть проверки свежего процесса. Для отдельной диагностики запуска:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_startup.py tests/test_launcher.py -q
if ($LASTEXITCODE -ne 0) { throw 'Проверка запуска завершилась ошибкой' }
```

`test_startup.py` запускает настоящий интерфейс в новом интерпретаторе: пустое окно и анализ демо, с приглашением обучения и без него, затем нормальное закрытие. `test_launcher.py` на Windows проверяет пакетный запуск, отдельный `pythonw.exe`, ошибки запуска и реальное окно с анализом демо. Настройки процессов изолированы временными INI. Mock-тесты сами по себе не заменяют эти проверки.

Перед выпуском вручную откройте `run.cmd`, дождитесь окна, нажмите «Попробовать демо», проверьте результаты и видимость версии слева внизу, откройте «Как пользоваться», затем закройте обучение и приложение. Убедитесь, что окно и процесс приложения закрылись. Ручной запуск использует обычные пользовательские настройки; автоматические тесты обязаны использовать явный временный INI без обращения к HKCU.

Новые возможности и изменения покрывайте успешными, ошибочными и граничными сценариями; исправления — регрессионным тестом. После последнего изменения повторите полную проверку. Не меняйте продукт после нее без нового прогона.

Обновляйте README.md и CHANGELOG.md вместе с поведением. Для выпуска измените `__version__` в `data_xray/__init__.py`: сборка и интерфейс используют его автоматически. CHANGELOG хранит добавленные, удаленные и измененные возможности каждой версии; версии JSON-схем меняются отдельно. Не указывайте неподтвержденные результаты CI или поддержку других платформ.

Не включайте в изменения частные датасеты, секреты и содержащие реальные значения отчеты. Не публикуйте уязвимости с чувствительными примерами в открытых обсуждениях; порядок описан в SECURITY.md. Репозиторий и лицензия выбираются владельцем отдельно.

## Состав репозитория

Публикуются исходники, тесты, инструменты проверки, синтетические примеры,
README, CHANGELOG, CONTRIBUTING, SECURITY и иллюстрации из `docs/public/`.
Локальные настройки помощников, рабочие планы и отчеты разработки не входят
в репозиторий. `.gitignore` исключает их при обычном добавлении файлов,
а `.gitattributes` — из исходных архивов.

Перед коммитом проверьте уже добавленные в Git файлы:

```powershell
.\.venv\Scripts\python.exe tools\check_repository.py
```

Проверка читает индекс Git, поэтому обнаружит запрещенный файл даже после
принудительного добавления. Она также выполняется в CI. Не обходите исключения
для публикации локальных заметок. Полезные пояснения алгоритмов и ограничений
должны оставаться в комментариях к коду или в документации для пользователей.
